# ChatBI 架构层级说明

## 1. 用户提问层
**含义**：业务人员用自然语言提出分析问题。  
**做了什么**：输入查询、连续追问、修改日期范围、触发下载与报告。

## 2. 前端交互层
**含义**：负责页面展示和用户交互。  
**做了什么**：
- 展示列表 / 柱图 / 饼图
- 展示指标定义、指标描述、维度、SQL
- 展示执行日志、下载任务、报告入口

## 3. 接入编排层
**含义**：系统请求总入口。  
**做了什么**：
- Flask API 接收请求
- 编排查询、导出、报告、后台维护
- 管理会话 ID、模型选择、返回结构

## 4. 会话与上下文层
**含义**：管理多轮对话和上下文记忆。  
**做了什么**：
- `chat_session / chat_message` 持久化
- 连续对话恢复
- 滚动摘要 + 最近窗口压缩上下文
- 判断“独立问题”还是“追问问题”

## 5. 语义层
**含义**：把自然语言问题先映射到业务语义，而不是直接查库。  
**做了什么**：
- 维护指标、维度、业务表、关联关系、同义词、问法示例
- 同步真实数据库字段结构
- 检索并收敛候选语义对象

**核心技术**：
- `semantic_*` 语义表
- MySQL FULLTEXT
- DashScope embedding
- `embedding_json + Python` 相似度召回

**说明**：当前不是 `pgvector`，后续可升级为 `pgvector / OpenSearch`。

## 6. Prompt 组装层
**含义**：把候选语义压缩后发给模型。  
**做了什么**：
- 只发送本轮相关指标、维度、表、必要字段、必要 join
- 限制 prompt 长度，减少无关 schema 噪音

## 7. 大模型查询规划层
**含义**：理解问题并生成查询计划。  
**做了什么**：
- 调用阿里百炼 `qwen3-max / DeepSeek`
- 输出 `action`、指标定义、指标描述、维度、指标、SQL、时间范围
- 信息不足时返回 `clarify` 追问

## 8. SQL 治理与执行层
**含义**：保证 SQL 安全、稳定、兼容 MySQL。  
**做了什么**：
- 白名单表校验
- 只允许 `SELECT / WITH`
- 自动补 `LIMIT`
- MySQL 方言归一化
- SQL 执行失败时自动进入 SQL 修复链路

**说明**：当前是只读查询，不涉及业务数据写入和事务回滚。

## 9. 数据执行层
**含义**：查询真实业务数据。  
**做了什么**：
- 访问订单、商品、用户、门店、退款等业务表
- 返回列名、结果集、行数

**核心业务表**：
- `order_master / order_detail`
- `user_info / product_info / store_info`
- `refund_master / refund_detail`
- `inventory_stock`

## 10. 结果输出层
**含义**：把查询结果变成业务可读内容。  
**做了什么**：
- 返回表格数据
- 支持柱图 / 饼图切换
- 展示指标定义、指标描述、维度、SQL
- 展示执行日志

## 11. 导出与报告层
**含义**：把数据结果沉淀成文件和管理层材料。  
**做了什么**：
- 明细导出 CSV
- 图表导出 Word
- 商业分析报告生成
- 模板管理、模板解析、报告历史留存

## 12. 异步任务层
**含义**：把耗时任务放到后台执行。  
**做了什么**：
- `async_task` 任务表
- `worker.py` 独立消费
- 处理报告生成、语义刷新重建
- 支持心跳、抢占、状态回写

## 13. 日志与监控层
**含义**：问题排查与质量监控。  
**做了什么**：
- `web.log / worker.log / error.log`
- `llm_invocation_log` 记录模型请求与返回
- 语义刷新结果展示
- 模型漏返字段统计
- 日志超 1GB 自动裁剪
